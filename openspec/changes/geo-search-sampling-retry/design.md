# Design

## Context

当前 GEO 文件包含结果及平台配置快照。实测 GPT 中转 Responses API 返回已完成的搜索调用和结构化引用。

## Goals / Non-Goals

**Goals**

- 同一 GPT 平台可按次请求联网，识图编辑仍走原通道。
- 有界采样与可追溯的失败补跑。

**Non-Goals**

本期聚焦一次检测的结果。周期监测和账户计费另行规划。

## Decisions

1. 使用 NiubiGEO Responses 适配器调用 GPT 中转联网接口。默认普通对话，联网上报以提供方执行信号为准，失败直接写入样本。
2. 每个平台顺序执行采样，平台之间可并行。保存平台 ID、样本序号和请求时的联网开关，原有单样本记录沿用原读取方式。
3. 补跑写新记录并引用来源，保留成功样本和序号。复测重新采样全部位置，继续校验配置和提示词版本。
4. 引用匹配删除固定集合的常见追踪参数，保留页面路径及其它参数。

## Risks / Trade-offs

- 多个样本增加模型消耗，提交前展示请求数量。成功数作为命中比例分母。
- 上游渠道可能暂时不可用。历史保留失败详情，补跑只请求仍失败的样本。

## Migration Plan

新字段随写入生成。旧记录缺少采样次数时视为一次，配置快照仍按原规则判断。
