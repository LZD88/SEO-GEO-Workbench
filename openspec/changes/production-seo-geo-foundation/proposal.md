# 曜见 YaoSight 生产化提案

## Why

YaoSight 已有技术 SEO 抓取、真实模型 API 采样、引用证据、同题复测和图文优化报告。当前部署和数据模型面向本机单用户，客户上线前需要项目隔离、可靠执行、调用成本控制，以及能解释和复核的持续监测口径。

## What Changes

- **第一批 · 受控试点底座**。增加邀请制工作空间和站点项目，持久化任务、样本和用量，隔离抓取运行环境，提供告警、备份和恢复流程。
- **第二批 · 可持续监测**。给 GEO 增加版本化问题集、定期采样、有限竞品对照和可追溯指标。给 SEO 增加已验证站点审计、URL 级问题列表、历史差异和修复复查。
- 保留本机启动和既有报告读取入口。生产环境采用独立部署配置，提供本地历史的显式导入路径。图文分析继续只开放给已验证具备识图能力的模型，文章导入和报告生成走同一套权限、用量和作业生命周期。
- 以邀请制团队版作为首个交付假设。首期以中文内容和可校验的 API 渠道为主，现有六个模型入口分别标注其实际能力与可用性。充值、订阅交易、消费者网页端采样、SERP 和反链数据库留待后续产品阶段。

## Capabilities

### New Capabilities

- `workspace-access` — 邀请、角色、项目归属、会话与数据隔离。
- `durable-job-execution` — 可恢复的作业、配额、用量和运行观测。
- `public-fetch-boundary` — 文章、图片、爬虫及后续渲染的受限出网策略。
- `geo-measurement` — 问题组、定期样本、来源口径、证据和竞品对照。
- `seo-site-audit` — 验证站点、受限抓取、标准化问题及按批次复查。

### Modified Capabilities

当前主规格为空。两个已实施的未归档变更继续提供已有行为约束，具体涉及证据分级、联网采样、补跑、复测、报告历史与下载。

## Impact

生产模式涉及 `server.mjs`、`local-auth.mjs`、`geo-checks.mjs`、`geo-platforms.mjs`、`article-reader.mjs`、`article-optimization.mjs`、报告存储和工作台页面。部署需要 TLS 入口、关系数据库、Web 与 Worker 进程、受限抓取环境和私有报告存储。

| 参考平台 | 已核对的公开能力 | YaoSight 的差距和顺序 |
| --- | --- | --- |
| Ahrefs Site Audit | JavaScript 渲染、可筛选技术问题、抓取前后比较、Core Web Vitals | 现有 SiteOne 原始报告需要转成项目内可定位、可分派优先级和可复查的问题。JS 渲染和真实用户性能数据后续单列。 [官方功能](https://ahrefs.com/site-audit) |
| Ahrefs Brand Radar | 自定义问题持续跟踪、竞品比较、AI 份额及大规模预采样索引 | 先做客户自己的固定问题集与同口径竞品对照。跨客户预采样索引需要持续数据投入。 [官方功能](https://ahrefs.com/brand-radar) |
| Semrush | 日级问题跟踪、竞品与引用分析，以及关键词和反链数据 | 先补同一问题集上的竞品和引用分析。关键词库、跨域排名和反链覆盖另选数据供应商并验证成本。 [AI Visibility](https://www.semrush.com/features/ai-visibility/) · [Keyword Research](https://www.semrush.com/features/keyword-research/) · [Backlinks](https://www.semrush.com/analytics/backlinks/) |
| Peec AI | 自定义问题、可见性跟踪和关键引用来源 | 目前可查看单次样本与基线，下一步补定期监测、来源聚合和项目趋势。 [官方功能](https://peec.ai/) |
| Profound | 引用分析、问题量产品和 AI 爬虫访问分析 | 先把自己采到的证据做扎实。需求规模需要独立数据来源，爬虫分析需要客户授权的服务器或 CDN 日志。 [官方功能](https://www.tryprofound.com/) |

技术审计稳定后，优先接入客户授权的 Search Console 数据，在自有站点上关联页面、查询、曝光、点击和排名，再验证 GA4 的引荐与转化口径。SEO 关键词库、跨域排名与反链需要额外数据源。专业 GEO 产品的品牌认知、份额、市场覆盖、引用变化提醒和代理商报告依赖稳定采样与历史，按客户实际需求立项。文章优化报告可以把引用和页面问题解释给内容团队，再用同题复测观察变化。

收费上线前，先用试点数据估算每个项目的月度用量和报告成本，再确定套餐、超额策略和客服处理流程。收费阶段需另行设计配额权益、支付回调去重、订单对账和退款。公开仓库当前未见项目级许可证，若准备开放第三方复用，还需明确项目授权和上游素材条款。

公开页面用于核对功能范围。平台的采样实现、覆盖率、结果准确度及规模未做实测。
