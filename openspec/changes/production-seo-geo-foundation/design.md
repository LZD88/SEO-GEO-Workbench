# 曜见 YaoSight 生产化设计

## Context

本机程序在 `server.mjs` 监听回环地址，`local-auth.mjs` 使用单账户文件和进程内会话。SEO、GEO 和文章报告分别写入本地目录。GEO 和 SEO 由进程内状态限制执行，GEO 样本主要在整次运行结束时一同持久化，文章报告在 HTTP 请求内调用模型并保存。Windows 安装器已锁定 SiteOne 和 NiubiGEO 的版本或提交。生产构建复用这两个上游，并独立验证 Linux 打包、报告格式与锁定依赖。

## Goals / Non-Goals

**Goals**

- 同一个任务可以在浏览器刷新、Web 重启或 Worker 重启后继续追踪，已确认为完成的结果可读取。
- 站点报告、复测和用量都能追溯到空间、项目及对应的运行快照。
- 保留既有的手动 GEO、文章优化和技术审计入口。产品交付以邀请制单区域试点及其运行边界为验收场景。

**Non-Goals**

- 首期交付范围限技术审计及有证据的 API 监测。公开自注册、支付、跨区域高可用承诺、消费者网页采样和第三方 SEO 数据采购单独立项。
- 大规模爬取、浏览器渲染、跨站获客归因和报告白标安排在后续迭代。

## Decisions

### 1. 延续 Node.js 应用，拆开 Web 和 Worker

保留现有 SiteOne 运行适配、NiubiGEO 提供商适配、样本分类和报告渲染逻辑。在当前代码库增加按工作空间授权的生产入口，Web 接收提交和查询，Worker 执行模型、文章和 SEO 任务。生产接口经 TLS 入口提供服务，从可信配置取得公开源地址。本机快速启动沿用 Windows 模式。评估过独立微服务和独立消息队列。试点期间选择同一应用与数据库事务，减少部署与双写协调。

PostgreSQL 管理成员、项目、任务、样本、计划、用量及报告元数据。任务表按状态和到期时间索引，使用短事务领取工作并记录租约与心跳。所有结果查询按工作空间及项目过滤并分页。数据库约束防止任务、基线、附件或下载关联到其他空间。产物使用私有对象存储，经授权接口传输，HTML 报告按附件响应。

### 2. 工作空间是授权和成本边界

生产模式接入受支持的 OIDC 身份提供方，通过已验证身份接受有期限的一次性邀请。本门户保存持久化、可撤销的服务端会话与成员关系。每次请求校验当前角色，统一校验写请求来源和会话，邀请活动、成员变更、用量调整和项目暂停进入审计日志。用户看到平台和渠道类型，密钥、上游地址、账单明细及中转账号留给运维。应用本地单密码适合现有回环模式，试点生产模式使用独立登录路由和配置。

### 3. 用事务和幂等保障恢复，把外部调用状态记录到单样本

写入任务、运行参数和预算预留后再返回任务标识。提交幂等键按空间、项目和任务类型约束。调度器按计划标识和 UTC 时段去重，保留业务时区。状态按任务与步骤记录，生成新报告前核对保存状态。已持久化的成功样本在故障恢复时直接沿用。用量账本分开记录调用次数、预留及渠道已知成本，确切成本不可得时显示估算或待核对。

调用前以短事务登记尝试，完成时在事务中保存样本和用量。外部请求使用供应商可用的幂等或查询能力。确认没有开始或明确可重试的失败才允许退避补跑，并限次、限总时长。供应商超时、执行后崩溃或结算不明时保留尝试记录和预留，待核对后再继续。取消阻止新的外部请求，对在途尽力停止并核算。简单的内存重试方案会丢失已执行工作，定时任务和人工重跑也使用同一套约束。

### 4. 网页抓取在独立受限执行环境运行

`article-reader.mjs` 已通过 NiubiGEO 的公开网页抓取工具处理正文和图片。SiteOne 的入口校验、授权勾选与抓取上限继续用于产品层，生产中给整个爬虫进程和全部网页请求加网络约束。读取任务在最小权限环境执行，通过受控出网访问允许的公开主机、协议和端口，检查实际连接与跳转，隔离私网、云元数据、控制面和其他项目资产。模型请求走独立通道，只允许管理员批准的上游。生产示例使用预置产物，届时可与本机示例分开配置。仅靠入口 URL 文字规则无法覆盖整个爬虫执行链。

受限进程没有数据库或模型密钥读取权限。为文章和图片设置请求时长、响应大小和类型上限，保持现有截断、图片缺失和改用粘贴正文提示。检查外部正文中出现的提示注入影响。图文报告生成保持无外部操作权限，展示内容经过现有安全渲染策略及回归验证。

### 5. 用可解释的 GEO 指标代替单一总分

继续使用现有逐样本证据。为周期运行保存问题集及版本、原问题、语言、请求地区（渠道实际支持时才记录有效地区）、渠道类型、配置模型和已知实际模型、请求联网、实际联网状态、时间及采样版本。已关闭、确认联网和未证实分别显示。设置变更和模型已知版本变化时切分历史，证据不足时展示结果和覆盖，暂停涨跌结论。

按模型和问题集展示计划、成功、失败、待核对和适用分母。品牌提及按有可判定证据的有效回答统计。正式引用与正文链接单独计算，来源归因依赖精确 URL 或用户明确登记的域名，记录采用了哪种口径。对同一个回答核对本品牌和少量显式配置的竞品，每个实体每类证据只计一次。聚合率来自所选问题集，允许多个实体同时命中。保留来源链接和可回溯原样本。拒绝把补跑沿用样本当成额外采样。大规模预采样或综合评分需要进一步评估题库偏差和渠道可比性。

能力验证使用由运营维护的小型固定样本，分别检查回答、实际联网、原生引用和图片输入回归。只有通过图像内容辨识验证且仍有效的具体模型和渠道组合可供文章报告使用。保存验证时间与版本，不在测试媒体中使用客户内容。产品界面明确 API 采样的覆盖范围，消费者端数据在取得授权和可验证的独立来源之后讨论。

### 6. 先把技术 SEO 报告变成能复查的问题

第一个生产验证方式采用 DNS TXT，记录验证状态及被授权的主机范围。配置包含入口、主机或路径、速率、页数和最大深度。接入 SiteOne 版本化 JSON 解析器，依据实际产物生成首批规则，把索引判定与抓取覆盖标明。缺少规则所需字段时，记录该规则不可判定。保存原报告以查明漏判和解析回归。

问题标识包括规范化 URL、规则及需要区分的受影响子项。审计快照保存抓取范围、规则版本和覆盖。对比时，只有成功且可比的规则复查能标记修复。技术可索引性来自站点页面与抓取规则。Google 索引、搜索曝光和点击由后续授权连接器单独提供。先保留原报告并增量映射，降低更换引擎或一次实现全部规则的风险。

## Risks / Trade-offs

- 上游返回成功后本地写入失败 → 保留待核对状态并按渠道查询或人工确认，运营可暂停故障渠道。
- 重新执行时外部样本和 SEO 页面已变化 → 逐样本记录时间，按版本分组，时间段之外补跑的样本在趋势中标明。
- 同名品牌、模型版本不可知、区域不受支持 → 使用显式别名和域名，保留未知证据，不混算可比趋势。
- 网页含客户内容或授权范围变化 → 使用私有产物、可配置保留期限并验证删除流程，重新检查授权范围。脱敏日志只记录标识、错误类别和聚合数据。
- SiteOne 输出和 NiubiGEO 接口升级 → 锁定依赖，使用固定产物及仿真渠道进行兼容回归，逐个渠道验证后启用。

## Migration Plan

1. 添加生产配置、数据迁移和独立 Worker，建立 CI 的一方测试与生产集成测试入口。把未启用渠道、抓取安全阻断、权限和隔离测试加入发布验收。现有回归用 `node --test 'test/*.test.mjs'`，限定项目自己的测试。全目录自动发现会一并运行 vendor 自带的用例与固定端口夹具。
2. 用测试空间联调，从定期作业关闭的状态启动，演练停止 Worker、恢复数据库和报告产物。试点验收建议使用 5 个测试空间各并发 2 个合规任务，约定首次领取 P95 ≤ 60 秒，区分上游执行耗时，并实测备份恢复 RPO ≤ 24 小时、RTO ≤ 4 小时。指标属于试点目标，发布后根据观测校准。
3. 本机历史通过显式离线导入，按旧记录 ID 和目标项目去重，回填关联，未知字段保持未知，原件保留。未结束记录作为历史中断条目导入，禁止因此触发任务。导入后校验数量、报告关联和角色权限。
4. 先按空间允许受邀成员运行和复查，再打开定期计划。出现故障时暂停调度和相关 Worker，保留已提交作业及数据库。部署采用兼容迁移和前一版本镜像，必要时从已验证备份恢复，恢复后先核对外部调用账本再放开调度。
