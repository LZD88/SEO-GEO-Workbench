# Design

## Context

曜见是单用户 Node.js 本机服务。现有 GEO 检测按次写入 JSON，文章优化请求返回 Markdown。

## Goals / Non-Goals

**Goals**

- 保存对照所需的证据和执行条件。新旧 GEO 文件可并存。
- 浏览器刷新后可以找回已生成报告，返回来源检测并复测。
- 以相同问题和配置提供可解释的前后对照。

**Non-Goals**

本阶段是本机产品验证。公网多用户、收费及固定周期监测另行规划。

## Decisions

1. GEO 样本保留原字段并新增平台 ID、实际模型版本和证据类型。检测单独记录运行时配置快照，快照保存模型、联网选项和不可读的路由指纹。旧字段缺失时按现存证据解释。
2. 复测由后端读取基线并校验当前配置。旧数据仅在平台名称明确可映射且用户选择按当前配置复测时使用当前设置。两次实际模型版本不一致时提示。保留单次采样，展示样本数和每个平台的结果。
3. 优化报告以独立 JSON 存放，使用带随机 ID 的原子文件发布。现有本机启动和数据备份方式可继续使用。条目预览和 Markdown 下载都经过原会话鉴权。
4. 平台最近成功时间记录在本次运行的进程内，来自业务调用。页面按需展示，不发起额外探测。

## Risks / Trade-offs

- 同题同配置仍有随机性。对照以样本证据呈现，避免把单次结果描述成趋势。
- 上游路由可能返回不同版本。显示返回的实际版本，并提示差异或未知。
- 老报告只存在浏览器中或已下载文件。归档从部署后的新报告开始。

## Migration Plan

启动升级后的服务。原有 GEO 记录按需兼容读取，报告目录首次访问时创建。回滚到前一版时保留原文件，新增字段和报告目录可随数据备份。
